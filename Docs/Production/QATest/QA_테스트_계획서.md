# QA / 테스트 계획서

## 0. 문서 목적

이 문서는 게임을 테스트할 때 **무엇을, 어떤 기준으로, 어떻게 보고할지**를 정리합니다.

- 지금은 혼자 핵심 기능을 테스트하는 단계지만, 나중에 동아리 부원들이 확장 기능을 추가하면서 버그가 늘어날 것을 대비해 **미리 양식과 기준을 정해두는 문서**입니다.
- **ver3 변경 사항**: T-01~T-09 실제 플레이 테스트 완료 처리. 구현 과정 영상 목록(3장) 추가. 문서 참조 최신화.

|---|---|---|

## 2. 테스트 유형

| 유형 | 설명 | 예시 |

## 5. 버그 리포트 양식 (GitHub Issue 기준)

GitHub Issue를 생성할 때 아래 템플릿을 사용합니다.

```
제목: [버그] 간단한 증상 요약

## 증상
무엇이 잘못되었는지 설명

## 재현 방법
1. ...
2. ...
3. ...

## 기대한 동작
원래는 어떻게 동작해야 하는지

## 실제 동작
실제로 어떻게 동작했는지

## 환경
- Unity 버전:
- 브랜치/커밋:

## 우선순위
Critical / Major / Minor (6장 기준 참고)

## 스크린샷 또는 영상 (선택)
```

---

## 6. 버그 우선순위 분류

| 우선순위 | 기준 | 예시 |
|---|---|---|
| Critical | 게임 진행이 불가능해짐 | 캐릭터가 바닥을 뚫고 떨어짐, 리스폰이 동작하지 않음 |
| Major | 핵심 기능은 동작하지만 의도와 다르게 동작 | 점프 높이가 스펙과 크게 다름, 카메라가 가끔 멈춤 |
| Minor | 플레이에는 큰 영향 없는 사소한 문제 | 이펙트 위치가 살짝 어긋남, 디버그 텍스트 오타 |

## 7. 확장 기능 테스트 가이드 (동아리 단계)

부원이 확장 기능을 추가할 때는 아래 순서를 따릅니다.

1. **개별 테스트**: 본인이 만든 기능만 단독으로 테스트
2. **PR 생성 전 체크**: 핵심 기능(T-01~T-09)이 깨지지 않았는지 간단히 재확인
3. **PR 리뷰 시 확인**: 리뷰어가 코드뿐 아니라 실제 플레이도 해보고 머지
4. **통합 테스트**: 여러 확장 기능이 `develop`에 모이면 기능 간 충돌 확인

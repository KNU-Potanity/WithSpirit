# 역할 분담 문서

## 0. 문서 목적

이 문서는 동아리의 네 가지 역할(**PM / 프로그래밍 / 기획 / 아트**)을 기준으로, 지금까지 작성된 기획·기술 문서들이 실제로 **누구의 작업으로 이어지는지**를 정리한 문서입니다.

- 지금은 혼자 핵심 기능(MVP)까지 전부 만들고 있지만, 이 문서는 **이후 합류할 부원들이 자신의 역할에서 무엇부터 봐야 하는지 감을 잡도록** 돕는 용도입니다.
- 즉, "1인이 세 역할을 모두 수행했을 때 각 역할이 맡았어야 할 부분"을 역할별로 나눠서 설명합니다.

---

## 1. 역할 개요

| 역할 | 핵심 책임 | 주로 참고하는 문서 |
|---|---|---|
| **PM** | 프로젝트 전체 진행 관리, 일정/문서 체계 관리, 역할 간 조율 | `ToDoList.md`, `문서작성_가이드라인.md`, `역할분담_문서.md`(본 문서), `README.md` |
| **기획** | 게임의 규칙, 수치, 레벨 구조를 설계 | `플랫포머_게임_기획서_ver9.md`, `플랫포머_게임_기획서_확장기능_ver3.md`, `레벨디자인_MVP_스테이지_ver4.md`, `캐릭터컨트롤_스펙_ver2.md`, `사운드_큐_리스트_ver2.md` |
| **프로그래밍** | 기획에서 정한 내용을 실제로 동작하게 구현 | `기술기획서_ver5.md`, `캐릭터컨트롤_스펙_ver2.md` |
| **아트** | 캐릭터/배경/이펙트 등 시각 요소 제작 | `아트스타일_가이드_ver3.md`, `에셋_네이밍_관리규칙_ver2.md`, `에셋_출처_라이선스_관리_ver1.md` |

> 기획/프로그래밍/아트 세 역할은 순서대로 의존하는 경우가 많습니다: **기획이 수치/구조를 정의 → 프로그래밍이 그 수치대로 동작을 구현 → 아트가 그 동작에 맞는 시각 표현을 제작**. 다만 작은 프로젝트에서는 병렬로 진행해도 무방합니다.
>
> **PM은 이 세 역할에 속하지 않고, 전체 진행을 조율하는 별도 역할입니다.** 특정 콘텐츠를 직접 만들지 않는 대신, 일정 관리·문서 체계·역할 간 커뮤니케이션을 책임집니다.

## 2. 핵심 기능(MVP) 단계에서의 역할 분담

| 작업 | 담당 역할 | 내용 |
|---|---|---|
| 핵심 기능 정의 (이동/점프/충돌/리스폰/목표/카메라) | 기획 | `플랫포머_게임_기획서_MVP.md` 작성 |
| 캐릭터 컨트롤 수치 결정 (속도, 점프 높이, 코요테 타임 등) | 기획 | `캐릭터컨트롤_스펙_MVP.md` 작성 |
| 레벨 구조 설계 (구간별 난이도 곡선) | 기획 | `레벨디자인_MVP_스테이지1.md` 작성 |
| 위 수치/구조를 Unity 코드로 구현 | 프로그래밍 | `기술기획서_MVP_Unity.md`에 정의된 구조대로 스크립트 작성 |
| Tilemap으로 실제 레벨 배치 | 프로그래밍 (또는 기획이 직접 배치 가능) | 레벨 디자인 문서의 패턴을 Unity 씬에 구현 |
| 캐릭터/발판/장애물 에셋 | 아트 (현재는 CraftPix SimplePlatformer2D 에셋 사용 중) | 추후 아트 부원이 직접 제작한 에셋으로 교체 가능 (`에셋_출처_라이선스_관리_ver1.md` 참고) |
| 전체 일정/문서 상태 점검 | PM | 각 역할의 산출물이 계획대로 진행되는지 확인, `ToDoList.md` 갱신 |

> MVP 단계는 "재미있는 핵심 동작을 만드는 것"이 목적입니다. 현재는 CraftPix SimplePlatformer2D 에셋을 임시로 사용 중이며, 추후 아트 부원이 제작한 에셋으로 교체할 수 있습니다.

## 3. 확장 기능 단계에서의 역할 분담

`플랫포머_게임_기획서_확장기능.md`의 항목들을 역할별로 다시 분류하면 아래와 같습니다.

### 3.1 기획이 주도하는 항목
| 확장 기능 | 기획이 할 일 |
|---|---|
| 적 시스템 | 적의 행동 패턴, 난이도, 배치 위치 설계 |
| 수집/보상 | 코인 개수, 배치 위치, 보상 조건 설계 |
| 생명/체력 확장 | 체크포인트 위치, 생명 개수 등 밸런스 설계 |
| 파워업 | 어떤 능력을, 어떤 조건으로 얻는지 설계 |

### 3.2 프로그래밍이 주도하는 항목
| 확장 기능 | 프로그래밍이 할 일 |
|---|---|
| 이동 확장 (더블 점프, 대시, 벽 점프) | 기획이 정한 수치대로 동작 구현 |
| 지형 확장 (이동 발판, 무너지는 발판, 스프링) | 새로운 지형 타입 추가 (기존 `TerrainType` 구조 확장) |
| UI (HUD, 일시정지 메뉴) | 이벤트 시스템에 UI 연결 |
| 카메라 확장 (자동 스크롤, 줌, 흔들림) | Cinemachine 설정 추가 |

### 3.3 아트가 주도하는 항목
| 확장 기능 | 아트가 할 일 |
|---|---|
| 캐릭터/적 비주얼 | 캐릭터, 적 스프라이트, 애니메이션 제작 |
| 배경/타일셋 | 스테이지 배경, 발판/장애물 타일 그래픽 |
| 이펙트 | 점프, 피격, 클리어 시 파티클/이펙트 |
| UI 비주얼 | HUD, 메뉴 디자인 (프로그래밍이 만든 기능에 입힐 디자인) |

### 3.4 협업이 필요한 항목 (사운드 등)
| 확장 기능 | 협업 방식 |
|---|---|
| 사운드 | 기획이 "어떤 상황에 어떤 느낌의 소리가 필요한지" 정의(`사운드_큐_리스트.md`) → 아트(또는 별도 사운드 담당)가 음원 제작/선정 → 프로그래밍이 이벤트에 연결 |

### 3.5 PM이 담당하는 항목
| 항목 | PM이 할 일 |
|---|---|
| 일정 관리 | 확장 기능별 마일스톤 설정 및 진행 상황 추적 (`일정_마일스톤.md`) |
| 문서 체계 관리 | 새 문서의 카테고리 분류, 버전 관리, README 링크 최신화 (`문서작성_가이드라인.md`) |
| 역할 간 조율 | 기획-프로그래밍-아트 간 의존관계(예: 수치 확정 전 구현 착수 방지) 조율 |
| 회의/의사결정 기록 | 결정 사항을 회의록 또는 관련 문서에 반영되도록 확인 |

## 4. 역할별 체크리스트 (이후 부원이 합류했을 때)

**PM 역할을 새로 맡거나 인수인계 받는다면**
- [ ] `문서작성_가이드라인.md`를 읽고 문서 체계(폴더 구조/버전/네이밍) 숙지
- [ ] `ToDoList.md`로 현재 진행 상황 파악
- [ ] `README.md` 링크가 최신 상태인지 점검
- [ ] 각 역할(기획/프로그래밍/아트)의 진행 상황을 주기적으로 확인하고 조율

**기획 역할이 새로 합류한다면**
- [ ] `README.md`의 문서 목록을 먼저 읽고, 어떤 수치/구조가 이미 정해져 있는지 파악
- [ ] 확장 기능 중 본인이 설계하고 싶은 항목 선택
- [ ] 수치/규칙을 문서화한 후 프로그래밍 담당과 공유

**프로그래밍 역할이 새로 합류한다면**
- [ ] `기술기획서_ver5.md`의 폴더 구조와 코딩 규칙 확인
- [ ] GitHub 저장소 클론 후 기존 코드 구조 파악 (Scripts 폴더 내 역할별 분리 확인)
- [ ] 맡을 확장 기능에 맞는 `feature/` 브랜치 생성

**아트 역할이 새로 합류한다면**
- [ ] 현재 사용 중인 임시 그래픽(플레이스홀더) 확인
- [ ] `아트스타일_가이드_ver3.md` 확인
- [ ] 제작한 에셋은 `에셋_네이밍_관리규칙_ver2.md` 규칙에 맞게 정리, 외부 에셋 사용 시 `에셋_출처_라이선스_관리_ver1.md`에 기록

# 역할 분담 문서

## 0. 문서 목적

이 문서는 동아리의 세 가지 역할(**프로그래밍 / 기획 / 아트**)을 기준으로, 지금까지 작성된 기획·기술 문서들이 실제로 **누구의 작업으로 이어지는지**를 정리한 문서입니다.

- 지금은 혼자 핵심 기능(MVP)까지 전부 만들고 있지만, 이 문서는 **이후 합류할 부원들이 자신의 역할에서 무엇부터 봐야 하는지 감을 잡도록** 돕는 용도입니다.
- 즉, 1인이 세 역할을 모두 수행했을 때 각 역할이 맡았어야 할 부분을 역할별로 나눠서 설명합니다.

---

## 1. 역할 개요

| 역할 | 핵심 책임 | 주로 참고하는 문서 |
|---|---|---|
| **기획** | 게임의 규칙, 수치, 레벨 구조를 설계 | `플랫포머_게임_기획서.md`, `플랫포머_게임_기획서_확장기능.md`, `레벨디자인_MVP_스테이지.md`, `캐릭터컨트롤_스펙.md`, `사운드_큐_리스트.md`, `정령_시스템_기획서.md`, `몬스터_기획서.md`, `발판_확장_기획서.md`, `스탯_기획서.md`, `월드_스테이지_구성.md` |
| **프로그래밍** | 기획에서 정한 내용을 실제로 동작하게 구현 | `기술기획서.md`, `캐릭터컨트롤_스펙.md` |
| **아트** | 캐릭터/배경/이펙트 등 시각 요소 제작 | `아트스타일_가이드.md`, `에셋_네이밍_관리규칙.md`, `에셋_출처_라이선스_관리.md` |

> 세 역할은 순서대로 의존하는 경우가 많습니다: **기획이 수치/구조를 정의 → 프로그래밍이 그 수치대로 동작을 구현 → 아트가 그 동작에 맞는 시각 표현을 제작**. 다만 작은 프로젝트에서는 병렬로 진행해도 무방합니다.

## 2. 핵심 기능(MVP) 단계에서의 역할 분담

| 작업 | 담당 역할 | 내용 |
|---|---|---|
| 핵심 기능 정의 (이동/점프/충돌/리스폰/목표/카메라) | 기획 | `플랫포머_게임_기획서.md` 작성 |
| 캐릭터 컨트롤 수치 결정 (속도, 점프 높이, 코요테 타임 등) | 기획 | `캐릭터컨트롤_스펙.md` 작성 |
| 레벨 구조 설계 (구간별 난이도 곡선) | 기획 | `레벨디자인_MVP_스테이지.md` 작성 |
| 위 수치/구조를 Unity 코드로 구현 | 프로그래밍 | `기술기획서.md`에 정의된 구조대로 스크립트 작성 |
| Tilemap으로 실제 레벨 배치 | 프로그래밍 (또는 기획이 직접 배치 가능) | 레벨 디자인 문서의 패턴을 Unity 씬에 구현 |
| 캐릭터/발판/장애물 에셋 | 아트 (현재는 CraftPix SimplePlatformer2D 에셋 사용 중) | 추후 아트 부원이 직접 제작한 에셋으로 교체 가능 (`에셋_출처_라이선스_관리.md` 참고) |

> MVP 단계는 재미있는 핵심 동작을 만드는 것이 목적입니다. 현재는 CraftPix SimplePlatformer2D 에셋을 임시로 사용 중이며, 추후 아트 부원이 제작한 에셋으로 교체할 수 있습니다.

## 3. 확장 기능 단계에서의 역할 분담

`플랫포머_게임_기획서_확장기능.md`의 항목들을 역할별로 다시 분류하면 아래와 같습니다.

### 3.1 기획이 주도하는 항목
| 확장 기능 | 기획이 할 일 |
|---|---|
| 정령 시스템 | 정령 6종 + 기본 정령의 세부 능력, 등장 타이밍, 세계관 설정 (`정령_시스템_기획서.md`) |
| 몬스터 시스템 | 몬스터 종류/배치/난이도 설계 (`몬스터_기획서.md`) |
| 발판 확장 | 이동/무너짐/스탯변화 발판의 배치와 효과 설계 (`발판_확장_기획서.md`) |
| 스탯 | 플레이어/정령/몬스터 스탯 항목 및 밸런스 (`스탯_기획서.md`) |
| 월드/스토리 | 테마 구성, 스토리 구체화 (`월드_스테이지_구성.md`) |
| 생명/체력 확장 | 하트 개수, 게임오버 조건 세부 밸런스 (`월드_스테이지_구성.md` 6~8장) |

### 3.2 프로그래밍이 주도하는 항목
| 확장 기능 | 프로그래밍이 할 일 |
|---|---|
| 정령 시스템 | 마커/클릭 상호작용, 정령 선택·전환, 공격/플랫폼 생성 로직 구현 |
| 몬스터 시스템 | 몬스터별 AI(근거리/원거리/디버프/보스), 데미지 판정 구현 |
| 발판 확장 (이동/무너지는/스탯변화) | 새로운 지형 타입 추가 (기존 `TerrainType` 구조 확장) |
| 체력 시스템 | 하트 UI 연동, 데미지/게임오버 처리 |
| UI | 하트, 정령 선택, 마커 등 신규 이벤트 시스템에 UI 연결 |

### 3.3 아트가 주도하는 항목
| 확장 기능 | 아트가 할 일 |
|---|---|
| 정령 비주얼 | 정령 7종 스프라이트/애니메이션 제작 (`아트스타일_가이드.md` 9.1절) |
| 몬스터 비주얼 | 몬스터·보스 스프라이트, 애니메이션 제작 (`아트스타일_가이드.md` 9.2절) |
| 발판/배경/타일셋 | 신규 발판 3종, 테마별 배경 그래픽 (`아트스타일_가이드.md` 9.3절) |
| 이펙트 | 정령 공격, 피격, 클리어 시 파티클/이펙트 |
| UI 비주얼 | 하트, 마커 디자인 (`아트스타일_가이드.md` 9.4절) |

### 3.4 협업이 필요한 항목 (사운드 등)
| 확장 기능 | 협업 방식 |
|---|---|
| 사운드 | 기획이 어떤 상황에 어떤 느낌의 소리가 필요한지 정의(`사운드_큐_리스트.md`) → 아트(또는 별도 사운드 담당)가 음원 제작/선정 → 프로그래밍이 이벤트에 연결 |

## 4. 역할별 체크리스트 (이후 부원이 합류했을 때)

**기획 역할이 새로 합류한다면**
- [ ] `README.md`의 문서 목록을 먼저 읽고, 어떤 수치/구조가 이미 정해져 있는지 파악
- [ ] `정령_시스템_기획서.md`, `몬스터_기획서.md`, `발판_확장_기획서.md`, `스탯_기획서.md`, `월드_스테이지_구성.md` — 확장 설계 현황 확인
- [ ] 아직 (추후 확정)으로 남아있는 스탯/스토리 항목 중 본인이 채울 부분 선택

**프로그래밍 역할이 새로 합류한다면**
- [ ] `기술기획서.md`의 폴더 구조와 코딩 규칙 확인
- [ ] GitHub 저장소 클론 후 기존 코드 구조 파악 (Scripts 폴더 내 역할별 분리 확인)
- [ ] 맡을 확장 기능에 맞는 `feature/` 브랜치 생성

**아트 역할이 새로 합류한다면**
- [ ] 현재 사용 중인 임시 그래픽(플레이스홀더) 확인
- [ ] `아트스타일_가이드.md` 확인 (9장 정령/몬스터/발판/UI 확장 가이드 포함)
- [ ] 제작한 에셋은 `에셋_네이밍_관리규칙.md` 규칙에 맞게 정리, 외부 에셋 사용 시 `에셋_출처_라이선스_관리.md`에 기록

# 정령 시스템 기획서

## 0. 문서 목적

이 문서는 확장 단계 핵심 시스템인 **정령**(플레이어를 따라다니며 돕는 동료)의 종류, 상호작용 방식, 등장 시점을 정의합니다.

- `플랫포머_게임_기획서_확장기능.md`에서 채택된 확장 기능의 상세 설계입니다.
- 정령 관련 수치(스탯 항목)는 `스탯_기획서.md`에 정리되어 있으며, 이 문서는 종류·역할·설정(세계관) 중심으로 작성합니다.
- 정령이 등장하는 테마별 시점은 `월드_스테이지_구성.md`를 참고하세요.

---

## 1. 정령 개요

| 항목 | 내용 |
|---|---|
| 정체 | 날아다니며 플레이어를 따라다니는, 플레이어를 돕는 동료 존재 |
| 체력 | 없음 (공격 대상이 되지 않고, 파괴·소멸되지 않음) |
| 역할 | 플레이어 대신 공격하거나 발판을 생성 |

> 플레이어 본인은 이동과 점프만 가능하고, 공격이나 특수 능력은 전부 정령을 통해 이루어집니다. (이동·점프 수치는 `캐릭터컨트롤_스펙.md` 기준 변경 없음)

## 2. 상호작용 방식

- 상호작용 가능한 대상(설치 장소, 몬스터 등)에 마우스 포인터를 가져다 대면 **마커**가 표시됩니다.
- 마커가 뜬 상태에서 클릭하면 아래처럼 동작합니다.

| 대상 | 클릭 시 동작 |
|---|---|
| 설치 장소 | 정령이 그 자리에 플랫폼을 생성 |
| 몬스터 | 정령이 공격해 몬스터에게 데미지 |

- 공격/기본 상호작용은 마우스 왼쪽 클릭, 정령 선택은 마우스 오른쪽 클릭입니다 (`캐릭터컨트롤_스펙.md` 조작키 참고).
- 마커 아이콘: `Assets/_Project/Art/UI/ui_marker_interact.png`.
- 마커와 마우스 커서 모두 **선택된 정령 고유 색상**을 따라갑니다 (커서는 `캐릭터컨트롤_스펙.md` 8.1절 참고). 커서가 몬스터/설치 마커 위에 있을 때는 마커에 가려지도록 커서 자신이 숨겨집니다.

### 2.1 공격 조건 및 쿨타임

- 쿨타임은 공격에만 적용됩니다 (플랫폼 변신에는 쿨타임 없음).
- 공격 조건: 몬스터 마커 활성화 **AND** 공격 쿨타임 경과 시 정령이 공격을 실행합니다.

### 2.2 플랫폼 변신 조건 및 방식 — 구현 완료 (`FairyPlatformController.cs`)

- 변신 조건: 플랫폼 설치 마커(`PlatformClickMarker.cs`)가 활성화되면 정령이 그 위치로 이동해 플랫폼으로 변신합니다.
- 흐름: 마커 위치까지 이동(이동 애니메이션 재생) → 도착 시 `MainFairyData.PlatformPrefab`을 그 자리에 `Instantiate` → Interact 애니메이션 재생 → 재생이 끝나면 정령의 `SpriteRenderer`/`Collider2D` 비활성화.
- 여러 설치 마커를 동시에 지원하며, 각 마커가 독립적으로 자기 상태(사용 중 여부)를 표시합니다.
- 이미 변신한 상태에서 다른 마커를 클릭하면 기존 플랫폼을 즉시 해제하고 쿨다운 없이 새 위치로 재변신합니다.
- 정령이 변신(이동 포함) 중일 때는 공격 요청이 무시되고, 반대로 몬스터를 클릭하면 플랫폼을 먼저 해제한 뒤 공격합니다 — 두 동작이 동시에 좌표를 움직이며 충돌하는 것을 막기 위함입니다.
- `env_platform_fairy_01.png`는 실제 플랫폼과 별개로, 마커 위치를 알려주는 장식용 스프라이트로만 쓰입니다.

### 2.3 플랫폼 변신 해제 조건 — 구현 완료

플랫폼으로 변신한 정령은 아래 중 하나를 만족하면 해제되어 원래대로 플레이어를 따라다닙니다.

- 몬스터도 설치 마커도 아닌 빈 공간을 좌클릭했을 때
- 화면 밖으로 벗어났을 때 (여유 마진 포함)
- 다른 설치 마커를 클릭했을 때 (이 경우는 해제가 아니라 즉시 재변신)

> 설계 원안과의 차이는 `QA_테스트_계획서.md` 11.1절 참고.

## 3. 정령의 종류

### 3.1 기본 정령 (1개, 원본)

- 게임 시작부터 항상 함께하며, 공격과 플랫폼 생성을 **모두** 사용할 수 있는 올라운드 정령입니다.
- 색상: **흰색**

### 3.2 추가 정령 (분신, 총 6종 중 3종 장착)

- 기본 정령의 분신이라는 설정이며, 테마 2부터 등장해 테마 3에서 최대 개수(3개)까지 함께합니다.
- 공격 또는 플랫폼 중 **한쪽에만 특화**되어 있습니다.

| 분류 | 종류 (3종) | 비고 |
|---|---|---|
| 공격 특화 | 폭발(주황) / 화상(빨강) / 빙결(파랑) | 각각 범위 폭발 / 지속 데미지 상태이상 / 행동불가 상태이상 — 수치는 `스탯_기획서.md` 2.2·4장 참고 |
| 플랫폼 특화 | 점프력 강화(노랑) / 이속 증가(하늘색) / 장막 제공(초록) | `발판_확장_기획서.md` 1.1절의 스탯 변화 발판 3종과 동일한 효과 |

### 3.3 기본 정령 vs 추가 정령

| 구분 | 기본 정령 | 추가 정령 |
|---|---|---|
| 기능 범위 | 공격 + 플랫폼 모두 | 공격 또는 플랫폼 중 하나 |
| 등장 시점 | 게임 시작부터 | 테마 2부터 |
| 개수 | 1개 (고정) | 최대 3개 (6종 중 선택) |

### 3.4 스테이지 시작 시 정령 구성

시작 스테이지(테마 1)를 제외한 다른 스테이지에서 시작할 때, 플레이어가 가지고 가는 정령은 **기본 정령 단 1개**뿐입니다. 추가 정령은 초기화되며, 해당 스테이지 안에서 7장의 획득 과정을 통해 다시 얻어야 합니다.

### 3.5 정령 대형(포메이션) 배치 규칙

정령들은 플레이어가 **바라보는 방향의 반대쪽**에 일렬로 늘어서며, **가장 먼저 얻은 정령(기본 정령 포함)이 플레이어와 가장 가깝고, 가장 나중에 얻은 정령이 가장 멀리** 위치합니다. 플레이어가 방향을 바꾸면 대형 전체가 반대편으로 재정렬됩니다.

### 3.6 실제 구현 현황 — 대형(줄서기) (`FairyManager.cs`)

- 플레이어의 좌우 방향에 따라 정령 전체 오프셋의 부호가 반전되어 3.5절 규칙대로 동작합니다.
- 대형에서 이탈한 정령의 슬롯은 비워지고 뒤쪽 정령들이 앞으로 당겨집니다.
- 정령들이 시간차를 두고 위아래로 출렁이는 물결(Wave) 효과가 있습니다.
- 현재는 Inspector에 프리팹을 직접 등록해 테스트 중이며, 7장의 실제 획득 UI와는 별개로 동작합니다.

### 3.7 실제 구현 현황 — 정령 선택 (`FairyManager.cs`)

마우스 오른쪽 클릭으로 정령을 선택/전환합니다.

- 일반 상황: 우클릭할 때마다 기본 정령 → 서브 정령들 순서로 순환.
- 몬스터 마커 호버 중 우클릭: 공격 가능한 정령끼리만 순환.
- 설치 마커 호버 중 우클릭: 플랫폼 변신 가능한 정령끼리만 순환.
- 마커를 실제로 클릭해 공격·변신을 실행할 때는, 선택 인덱스와 무관하게 해당 기능을 가진 가장 가까운 정령을 자동으로 찾아 사용합니다.
- 선택이 바뀔 때마다 이벤트가 발생해 커스텀 마우스 커서 색이 함께 바뀝니다.
- `FairyAttackController`/`FairyPlatformController`가 각각 `IFairyAttack`/`IFairyPlatform` 인터페이스를 구현해, 마커가 특정 컨트롤러를 직접 참조하지 않고 `FairyManager`를 통해 동적으로 정령을 찾습니다.

### 3.8 실제 구현 현황 — 공격 특화 정령 3종

폭발/화상/빙결 정령은 각각 전용 컨트롤러(`FairyExplosionAttackController.cs`/`FairyBurnAttackController.cs`/`FairyFreezeAttackController.cs`)로 구현되어 있으며, 기본 정령과 같은 돌진→적중→복귀 흐름을 공유하고 적중 시 처리만 다릅니다. 정령마다 전용 데이터 에셋(`ExplosionFairyData` 등 6종)이 분리되어 있습니다.

| 정령 | 동작 |
|---|---|
| 폭발 | 적중 지점 반경 안 몬스터 전체에게 데미지, VFX 재생 |
| 화상 | `MonsterBurnEffect` 부여 (지속 데미지 상태이상), 빙결과 상호 배제(중복 적용 안 됨) |
| 빙결 | `MonsterFreezeEffect` 부여, 이동/공격 전부 정지 |

> 수치·색상 등 설계 대비 차이는 `QA_테스트_계획서.md` 11.1절 참고.

### 3.9 발견된 버그 — 여러 몬스터가 같이 타겟팅됨

몬스터 여러 마리가 겹쳐있거나 인접해 있을 때, 마우스를 하나에 올려도 여러 마커가 동시에 활성화되거나 의도치 않은 몬스터가 타겟팅되는 버그가 있습니다. `MonsterClickMarker.cs`에 전역 단일 타겟팅 로직이 있지만 완전히 해결되지 않았습니다. 상세는 `QA_테스트_계획서.md` 10장 참고.

## 4. 플레이어와 정령의 관계 (세계관·감성 설정)

기능적으로는 무기·패시브 스킬과 다르지 않지만, 이 게임에서는 정령을 **플레이어와 함께 고생하며 스테이지를 뚫고 나가는 동료(자아의 일부)**로 설정합니다. 기능은 동일해도 세계관과 연출에 따라 다르게 다가올 수 있다는 것이 의도이며, 스토리(`스토리.md`)와 연결됩니다.

## 5. 애니메이션

### 5.1 애니메이션 종류 및 스펙

| 종류 | 설명 | 재생 속도 |
|---|---|---|
| 멈춤 (기본) | 제자리에 떠 있는 대기 상태 | 기준 속도 (10프레임) |
| 이동 | 플레이어를 따라 이동하는 상태 | 멈춤의 2배 속도 |
| 공격 | 공격을 실행하는 상태 | 기준 속도 |
| 상호작용 | 변신 효과가 함께 적용되는 상태 | 기준 속도 |

### 5.2 진행 상황 — 구현 완료

- **이동**(`FairyMovement.cs`): `SmoothDamp`로 플레이어+오프셋 위치를 추적, `Sin` 곡선으로 Hover 효과, 반대편이면 좌우 반전. `LockFollow()`/`UnlockFollow()`가 참조 카운터 방식이라 공격과 플랫폼 변신이 동시에 추적을 잠가도 꼬이지 않습니다.
- **공격**(`FairyAttackController.cs`): 몬스터 마커 클릭 시 대상에게 돌진 → `MonsterHealth.TakeDamage()` 호출 → 복귀 → 추적 재개. 기본 정령 기준 Damage=5, CoolTime=0.5초.
- **기본 정령 Animator**(`AC_Fairy_Base.controller`, 파라미터 `Speed`/`Interact`/`Arrived`): Idle/Move/InteractMove/InteractArrive/Interact 상태로 구성.
  - `Interact` 트리거는 플랫폼 변신(`FairyPlatformController.cs`)에서만 호출되며, 도착 시 `Arrived`/`InteractArrive`를 거치지 않고 `Animator.Play("Interact",0,0f)`로 직접 재생합니다.
  - 공격(`FairyAttackController.cs`)은 이 Animator와 무관하게 동작합니다 (Speed/Interact 파라미터 연동은 8장 다음 단계 참고).
- **플랫폼 변신/해제**(`FairyPlatformController.cs`) 및 **밀쳐내기**(`FairyPlatformEntityPusher.cs`, 활성화된 플랫폼 영역의 Dynamic Rigidbody를 밀어올림)는 2.2·2.3절 참고.

## 7. 정령 획득 UI

추가 정령을 얻는 시점에 3개의 후보 카드 중 하나를 선택하는 UI입니다 (3.2절 "6종 중 3종 선택 장착"과 연결).

### 7.1 레이아웃

카드 3개가 가로로 배치되며, 각 카드는 위에서부터 분류 라벨(공격 특화=빨강, 플랫폼 특화=파랑 글자) → 요정 이미지 → 요정 이름 → 요정 설명(왼쪽 정렬) 순으로 구성됩니다. 화상/빙결 설명 안의 상태이상 이름("화상"=빨강, "빙결"=파랑)에 마우스를 올리면 상세 수치 툴팁이 뜹니다.

### 7.2 획득 절차 및 후보 규칙

- 획득 트리거: 스테이지 내 특정 오브젝트에 플레이어가 닿으면 카드 선택 UI가 뜹니다.
- 6종 중 **무작위로 3개**가 후보로 나오며, **이미 획득한 정령은 제외**됩니다.
- 고른 정령은 정령 대형에서 **가장 마지막 위치**에 추가됩니다.

### 7.3 카드에 표시되는 정령별 정보

| 요정 이름 | 분류 | 색깔 | 요정 설명 |
|---|---|---|---|
| 폭발 정령 | 공격 특화 | 주황색 | 공격한 몬스터를 기준으로 광역 피해를 입힙니다. |
| 화상 정령 | 공격 특화 | 빨강색 | 공격한 몬스터에게 2초마다 1데미지를 입히는 **화상** 효과를 부여합니다. |
| 빙결 정령 | 공격 특화 | 파랑색 | 공격한 몬스터에게 3초동안 이동 및 공격을 정지시키는 **빙결** 효과를 부여합니다. |
| 점프력 강화 정령 | 플랫폼 특화 | 노랑색 | 점프 높이 1.5배 발판을 설치합니다. |
| 이속 증가 정령 | 플랫폼 특화 | 하늘색 | 3초간 이동 속도 1.5배 발판을 설치합니다. |
| 장막 제공 정령 | 플랫폼 특화 | 초록색 | 데미지 1회를 막아주는 장막 발판을 설치합니다. |

> 상세 스탯 수치는 `스탯_기획서.md` 2.2·2.3절 참고.

### 7.4 실제 구현 현황 — UI 뼈대

씬(`FairySelectPanel`)에 카드 3개가 7.1절 레이아웃대로 구현되어 있으며(분류 라벨 색상·설명 정렬 확인됨), 카드마다 `Button`+`Outline` 컴포넌트가 있어 클릭·선택 강조가 가능합니다. `StatusEffectTooltip.cs`가 카드 3장 모두에 연결되어 있습니다.

### 7.5 실제 구현 현황 — 선택 로직

후보 추첨·획득 처리 로직이 완성됐습니다 (`FairyInfo.cs`, `FairyPool.cs`, `FairySelectTrigger.cs`, `FairySelectUI.cs`).

- 보유 중인 정령(기본+서브)을 기준으로 후보에서 제외, 남은 후보 중 무작위 3개 추첨 — 7.2절 설계와 일치.
- 카드 클릭 시 정령 프리팹을 생성하고 `FairyManager.RegisterSubFairy()`로 등록.
- 선택 UI가 열려있는 동안 게임이 일시정지됩니다(`Time.timeScale=0`, 옵션으로 끌 수 있음). 보유 정령이 6종 다 채워지면 선택 UI 자체가 열리지 않습니다.

### 7.6 실제 구현 현황 — 씬 배선

`BossTest.unity`에 UI·트리거·`FairyPool.asset`(정령 6종 전체, 색상까지 팔레트와 일치)이 전부 연결되어, 트리거에 닿으면 실제로 선택 UI가 뜨고 획득까지 동작합니다.

- 이 배선은 `BossTest.unity`에만 되어 있고, 실제 플레이 씬에는 프리팹(7.7절)으로 배치해야 합니다. 데이터 에셋 수치 관련은 `QA_테스트_계획서.md` 11.1절 참고.

### 7.7 실제 구현 현황 — 재사용 프리팹화

정령 선택 UI·트리거가 재사용 가능한 프리팹 2개로 정리되었습니다.

| 프리팹 | 경로 | 내용 |
|---|---|---|
| `Canvas.prefab` | `Prefabs/UI/` | `HeartContainer`+`FairySelectUIManager`+`FairySelectPanel`+`StatusEffectTooltipPanel` 등 플레이 UI 전체 |
| `Select.prefab` | `Prefabs/Terrain/` | 정령 획득 트리거. `FairySelectUI.Instance` 싱글턴으로 자동 연결되어 어느 씬에 놓든 별도 연결 작업 없이 동작 |

`Stage3.unity`에 `Select.prefab` 인스턴스가 2개 배치되어 있습니다.

### 7.8 실제 구현 현황 — 정령 여러 마리 동시 운용

- 설치 마커 색상이 실제로 출격할 정령의 색을 따라갑니다 (`PlatformClickMarker.cs`가 `FairyManager.GetBestFairyForPlatform()`으로 미리 확인).
- 다른 마커를 클릭하면 활성화되어 있던 다른 모든 정령의 플랫폼이 한꺼번에 해제되어(`FairyManager.RevertAllActivePlatforms()`), 플랫폼은 항상 최대 1개만 유지됩니다.
- 플랫폼 특화 정령 3종이 각자 맞는 플랫폼 프리팹에 정확히 연결되어 있습니다 (`JumpBoostFairyData→JumpBoostPlatform` 등).

# 정령 시스템 기획서

## 0. 문서 목적

- `플랫포머_게임_기획서_확장기능.md`에서 채택된 확장 기능의 상세 설계입니다.

- 정령이 등장하는 테마별 시점은 `월드_스테이지_구성.md`를 참고하세요.

## 1. 정령 개요

| 항목 | 내용 |
|---|---|
| 정체 | 날아다니며 플레이어를 따라다니는, 플레이어를 돕는 동료 존재 |
| 체력 | 없음 (공격 대상이 되지 않고, 파괴·소멸되지 않음) |
| 역할 | 플레이어 대신 공격하거나 발판을 생성 |

> 플레이어 본인은 이동과 점프만 가능하고, 공격이나 특수 능력은 전부 정령을 통해 이루어집니다. (이동·점프 수치는 `캐릭터컨트롤_스펙.md` 기준 변경 없음)

## 2. 상호작용 방식

- 상호작용 가능한 대상(설치 장소, 몬스터 등)에 마우스 포인터를 가져다 대면 **마커**가 표시됩니다.
- 마커가 뜬 상태에서 클릭하면 아래처럼 동작합니다.

| 대상 | 클릭 시 동작 |
|---|---|
| 설치 장소 | 정령이 그 자리에 플랫폼을 생성 |
| 몬스터 | 정령이 공격해 몬스터에게 데미지 |

- 공격/기본 상호작용은 마우스 왼쪽 클릭, 정령 선택은 마우스 오른쪽 클릭입니다. (`캐릭터컨트롤_스펙.md` 조작키 항목 참고)
- **마커 아이콘**: `Assets/_Project/Art/UI/ui_marker_interact.png`에 배치 완료했습니다 (2026-07-23).
- **마커 색상**: 정령 상호작용(공격/플랫폼 변신) 시 뜨는 마커, 그리고 7장 정령 선택 UI에서 쓰이는 마커 모두 **해당 정령 고유 색상**을 따라갑니다 (예: 화상 정령의 몬스터 공격 마커는 빨간색, 이속 증가 정령의 설치 마커는 하늘색) (2026-08-18 추가).
- **마우스 커서 색상도 연동됨** (2026-08-18~20 추가, `CustomMousePointer.cs`): 게임 내 커스텀 마우스 포인터(8.1절)가 현재 선택된 정령의 색으로 물듭니다. 정령을 전환하면 커서 색도 즉시 바뀝니다. 다만 커서가 몬스터/설치 마커 위에 있을 때는 마커 표시에 가려지도록 커서 자신이 숨겨집니다.

### 2.1 공격 조건 및 쿨타임 (2026-07-23 추가)

- **쿨타임은 공격에만 적용**됩니다 (플랫폼 변신에는 쿨타임이 없습니다).
- **공격 조건**: 특정 몬스터의 마커가 활성화되어 있음 **AND** 공격 쿨타임이 지났을 때 → 정령이 공격을 실행합니다.

### 2.2 플랫폼 변신 조건 및 방식 — ✅ 구현 완료 (2026-07-23 설계 → 2026-08-04 구현 → 2026-08-04 로직 조정)

- **변신 조건**: 맵 내 지정된 위치의 플랫폼 설치 마커(`PlatformClickMarker.cs`)가 활성화되었을 때 → 정령이 플랫폼으로 변신합니다.
- **실제 구현 흐름** (`FairyPlatformController.cs`의 `TransformRoutine()`):
  1. `Interact` 트리거 발동 + `Speed=1`로 설정한 채, 마커 위치까지 정령을 직접 이동(`Vector3.MoveTowards`)시킵니다 — 이동 중에는 이동 애니메이션이 재생됩니다.
  2. 도착하면 **플랫폼 프리팹을 그 자리에 `Instantiate`로 새로 생성**하고, `Animator.Play("Interact", 0, 0f)`로 Interact 상태를 즉시 강제 재생합니다.
  3. Interact 애니메이션이 실제로 끝나는 시점(`normalizedTime` 폴링으로 정확히 감지)에 정령의 `SpriteRenderer`와 `Collider2D`를 비활성화합니다.
- ⚠️ **설계와 다른 점**: "도착 후 멈춤 애니메이션 1회" 단계는 여전히 생략되어 있고, `Arrived`/`InteractArrive`는 사용되지 않습니다 (Animator.Play()로 Interact 직행).
- **플랫폼 실체 (2026-08-04 변경)**: 기존에는 마커의 자식으로 미리 배치해둔 Tilemap 오브젝트를 켜고 끄는 방식이었는데, 이제는 **`MainFairyData.PlatformPrefab`에 지정된 프리팹을 변신 시점에 새로 생성(`Instantiate`)하고, 해제 시 `Destroy`하는 방식**으로 바뀌었습니다. 생성 위치는 마커 위치 + `MainFairyData.PlatformSpawnOffset`입니다. 생성된 인스턴스에 `FairyPlatformEntityPusher.cs`가 자동으로 붙어서 겹친 플레이어/몬스터를 밀어올립니다.
- **여러 마커 동시 지원 (2026-08-04 추가)**: 이전에는 마커 하나만 상정한 구조였는데, 이제 마커별로 어떤 마커가 지금 플랫폼을 쓰고 있는지(`FairyPlatformController.IsMyMarkerActive()`) 구분할 수 있어, 씬에 설치 장소가 여러 개 있어도 각 마커가 독립적으로 자기 상태를 표시합니다.
- **다른 마커 클릭 시 즉시 전환 (2026-08-04 추가)**: 이미 플랫폼으로 변신한 상태에서 **다른 설치 마커를 클릭하면, 기존 플랫폼을 즉시 해제(`Destroy`)하고 쿨다운 없이 바로 새 위치로 재변신**합니다(`RequestTransformOrReplace`). 단, 정령이 공격 중이면 이 전환도 막힙니다.
- **정령 공격과의 상호 배제 (2026-08-04 추가)**: 정령이 플랫폼으로 변신 중(이동 포함)일 때는 공격 요청(`FairyAttackController.RequestAttack`)이 무시되고, 반대로 몬스터 마커를 클릭하면 플랫폼 상태를 먼저 해제한 뒤 공격합니다. 두 코루틴이 동시에 `transform.position`을 움직이며 충돌하는 문제를 막기 위한 처리입니다.
- **임시 플랫폼 스프라이트**: `env_platform_fairy_01.png`(2026-07-28 배치)는 이제 실제 플랫폼 프리팹과는 별개로, 마커 위치를 알려주는 장식용으로만 쓰이고 있습니다.

### 2.3 플랫폼 변신 해제 조건 — ✅ 구현 완료 (2026-07-23 설계 → 2026-08-04 구현 → 2026-08-04 로직 조정)

플랫폼으로 변신한 정령은 아래 조건 중 하나를 만족하면 변신이 해제됩니다. 해제되면 비활성화되어 있던 정령이 **플랫폼이 있던 위치에서 다시 활성화**되고, `FairyMovement`가 다시 플레이어를 추적하며 원래대로 따라다니는 상태로 복귀합니다.

- **몬스터도 설치 마커도 아닌 빈 공간을 좌클릭했을 때** (2026-08-04 변경 — 이전에는 "좌클릭 = 공격 키"로만 취급했는데, 이제 몬스터 마커를 클릭하면 공격으로, 설치 마커를 클릭하면 즉시 재변신으로, 그 외 빈 공간을 클릭하면 단순 해제로 각각 다르게 처리됩니다)
- 플랫폼으로 변신한 정령이 카메라 화면 밖으로 벗어났을 때 (뷰포트 기준 판정, 상하좌우에 약간의 여유 마진 포함)
- 다른 설치 마커를 클릭했을 때 — 이 경우는 단순 해제가 아니라 **그 자리에서 바로 새 위치로 재변신** (2.2절 "다른 마커 클릭 시 즉시 전환" 참고)

⚠️ **설계와 다른 점**: 설계 원안은 "공격 쿨타임이 지난 상태에서 공격 키를 눌렀을 때"였는데, 실제 구현은 빈 공간 좌클릭 자체가 해제 트리거이고 공격 쿨타임과는 무관합니다. 다만 몬스터를 공격하려는 클릭은 별도로 처리되고(플랫폼을 먼저 해제한 뒤 공격 실행), 다른 마커로의 전환은 정령이 공격 중이 아닐 때만 가능하도록 막혀 있어 완전히 무제한은 아닙니다.

## 3. 정령의 종류

### 3.1 기본 정령 (1개, 원본)

- 게임 시작부터 항상 함께합니다.
- 공격과 플랫폼 생성 기능을 **모두** 사용할 수 있는 올라운드 정령입니다.
- 색상: **흰색** (2026-08-12 확정)

### 3.2 추가 정령 (분신, 총 6종 중 3종 장착)

- 기본 정령의 분신이라는 설정이며, 테마 2부터 등장하기 시작해 테마 3에서 최대 개수(3개)까지 함께합니다.
- 한 번에 함께하는 추가 정령 수는 최대 3개이며, 아래 6종 중 3종을 선택해 장착합니다.
- 기본 정령과 달리 공격 또는 플랫폼 중 **한쪽에만 특화**되어 있습니다.

| 분류 | 종류 (3종, 2026-08-12 확정) | 비고 |
|---|---|---|
| 공격 특화 | 폭발(주황) / 화상(빨강) / 빙결(파랑) | 각각 다른 공격 방식 (범위 폭발, 지속 데미지 상태이상, 행동불가 상태이상) — 상세 수치는 `스탯_기획서.md` 2.2절·4장 참고 |
| 플랫폼 특화 | 점프력 강화(노랑) / 이속 증가(하늘색) / 장막 제공(초록) | 정령이 생성한 플랫폼에 탑승 시 효과 부여. `발판_확장_기획서.md` 1.1절의 스탯 변화 발판 3종과 동일한 효과 |

> 정령마다 구분되는 색상을 부여할 예정입니다 (아트 확정 시 `아트스타일_가이드.md`에 반영).

### 3.3 기본 정령 vs 추가 정령

| 구분 | 기본 정령 | 추가 정령 |
|---|---|---|
| 기능 범위 | 공격 + 플랫폼 모두 | 공격 또는 플랫폼 중 하나 |
| 등장 시점 | 게임 시작부터 | 테마 2부터 (중간부터) |
| 개수 | 1개 (고정) | 최대 3개 (6종 중 선택) |

### 3.4 스테이지 시작 시 정령 구성 (2026-08-18 추가)

- **시작 스테이지(테마 1)를 제외한 다른 스테이지에서 시작할 때**, 플레이어가 가지고 가는 정령은 **기본 정령 단 1개**뿐입니다. 이전 스테이지에서 얻었던 추가 정령들은 이어지지 않고 초기화됩니다.
- 추가 정령은 해당 스테이지 안에서 7장의 획득 과정을 통해 다시 얻어야 합니다.

### 3.5 정령 대형(포메이션) 배치 규칙 (2026-08-18 추가, 2026-08-18 정렬 순서 정정)

정령들은 항상 플레이어가 **바라보는 방향의 반대쪽**에 일렬로 늘어섭니다.

| 플레이어 방향 | 정령 배치 위치 | 정렬 순서 |
|---|---|---|
| 오른쪽을 바라볼 때 | 플레이어 **왼쪽** | 먼저 얻은 정령일수록 플레이어와 더 **가까움** |
| 왼쪽을 바라볼 때 | 플레이어 **오른쪽** | 먼저 얻은 정령일수록 플레이어와 더 **가까움** |

- 즉, **가장 먼저 얻은 정령(기본 정령 포함)이 플레이어와 가장 가깝고, 가장 나중에 얻은 정령이 가장 멀리 위치**합니다.
- 플레이어가 좌우 방향을 바꾸면 정령 대형 전체가 반대편으로 다시 정렬됩니다.
- 7.2절의 "선택한 정령은 대형에서 가장 마지막 위치에 추가"는 이 규칙에 따라 **플레이어와 가장 먼 자리**를 의미합니다.

### 3.6 실제 구현 현황 — 대형(줄서기) (2026-08-18 추가, `FairyManager.cs`)

정령 줄서기(대형) 기능이 구현 완료됐습니다.

- 플레이어의 `SpriteRenderer.flipX`(또는 `localScale.x`)로 좌우 방향을 판정해, 정령 전체 오프셋의 X부호를 매 프레임 반전시킵니다 — **"바라보는 방향의 반대쪽에 늘어선다"는 규칙 자체는 3.5절과 일치**합니다.
- 기본 정령이 가장 안쪽(플레이어와 가장 가까운 고정 오프셋), 추가 정령들은 그 뒤로 순서대로 이어집니다.
- 공격/변신으로 대형에서 이탈한 정령(`IsFollowing == false`)은 그 순간 슬롯을 비우고, 뒤에 있던 정령들이 앞으로 당겨지는(연쇄) 방식으로 처리됩니다.
- **2026-08-20 추가**: 정령들이 순서대로 살짝 시간차를 두고 위아래로 출렁이는 **물결(Wave) 효과**가 추가됐습니다 (뒤쪽 정령일수록 앞쪽 정령의 호버링 파동을 지연 전달받음).

✅ **정렬 순서를 실제 구현(`FairyManager.cs`) 기준으로 확정했습니다.** 먼저 등록된(먼저 얻은) 정령일수록 앞쪽 슬롯(플레이어와 더 가까움)을 차지하고, 나중에 얻은 정령일수록 뒤쪽(더 먼) 슬롯에 배치되는 것이 맞는 설계입니다 (2026-08-18 확정).

- 현재는 `testSubFairyPrefabs`(Inspector에 프리팹을 직접 등록하면 시작 시 자동 생성) 방식으로 테스트 중이며, 7장의 실제 획득 UI와는 아직 연결되지 않은 것으로 보입니다.

### 3.7 실제 구현 현황 — 정령 선택 (2026-08-18 추가, `FairyManager.cs`)

마우스 오른쪽 클릭으로 정령을 선택/전환하는 기능이 구현 완료됐습니다 (`ToDoList.md`의 "정령 선택/전환 로직" 항목 완료).

- **일반 상황**(마우스가 몬스터/설치 마커 위에 없을 때): 우클릭할 때마다 기본 정령 → 서브 정령 1 → 서브 정령 2 → ... 순서로 순환 선택됩니다.
- **몬스터 마커에 마우스를 올린 상태**에서 우클릭: 공격 기능이 있는 정령(`IFairyAttack` 구현체)만 대상으로 순환합니다.
- **설치 마커에 마우스를 올린 상태**에서 우클릭: 플랫폼 변신 기능이 있는 정령(`IFairyPlatform` 구현체)만 대상으로 순환합니다.
- 몬스터/설치 마커를 클릭(좌클릭)해서 실제로 공격·변신을 실행할 때는, 사용자가 명시적으로 선택해둔 정령이 아니어도 **그 대상에 맞는 기능을 가진 가장 가까운 정령을 자동으로 찾아 사용**합니다 (`GetBestFairyForAttack`/`GetBestFairyForPlatform`) — 선택 인덱스 자체는 바뀌지 않습니다.
- 정령이 선택될 때마다 `OnFairySelected` 이벤트가 발생하며, 이 이벤트로 커스텀 마우스 커서(8.1절 참고)의 색이 선택된 정령 색으로 바뀝니다.

**공용 인터페이스 도입**: `FairyAttackController`/`FairyPlatformController`가 각각 `IFairyAttack`/`IFairyPlatform` 인터페이스를 구현하도록 리팩터링되어, 몬스터/설치 마커가 특정 컨트롤러를 직접 참조하지 않고 `FairyManager`를 통해 "공격 가능한 정령", "변신 가능한 정령"을 동적으로 찾습니다. `IMonsterMovement`/`IBarrierConsumable`과 같은 패턴입니다.


### 3.8 실제 구현 현황 — 공격 특화 정령 3종 — ✅ 완료 (2026-08-20 구현, 2026-08-20 마무리)

폭발/화상/빙결 정령이 각각 전용 컨트롤러(`FairyExplosionAttackController.cs`/`FairyBurnAttackController.cs`/`FairyFreezeAttackController.cs`)로 구현 완료됐습니다. 셋 다 기본 정령(`FairyAttackController.cs`)과 같은 돌진→적중→복귀 흐름을 공유하고, 적중 시 처리만 다릅니다.

**전용 데이터 에셋 분리 완료**: 기존에는 정령 6종이 전부 `MainFairyData.asset` 하나를 공유했는데, 이제 정령마다 **각자의 데이터 에셋**을 갖습니다 — `ExplosionFairyData`/`BurnFairyData`/`FreezeFairyData`(공격 특화), `JumpBoostFairyData`/`SpeedBoostFairyData`/`BarrierFairyData`(플랫폼 특화). 6개 모두 프리팹에 정확히 연결되어 있습니다.
- ⚠️ 다만 6개 모두 클래스는 여전히 `MainFairyData` 그대로이고(전용 `AttackFairyData`/`PlatformFairyData` 클래스는 안 쓰임), 값도 전부 기본값(Damage=1, CoolTime=0.5) 그대로라 `스탯_기획서.md` 2.2·2.3절에서 정한 정령별 개별 수치(예: 화상 공격력 0, 쿨타임 1.5)는 아직 반영되지 않았습니다.

**폭발 정령**
- 적중 지점에서 반경(`explosionRadius`, 기본 2.5유닛) 안의 모든 몬스터에게 데미지 — ⚠️ 2.2절에서 설계한 "3×3 범위"가 아니라 **원형 범위(반경 2.5)** 로 구현되어 있습니다.
- 적중 지점에 폭발 VFX(`AC_FX_Explosion.controller`, 5.2절 참고)가 재생 후 자동 삭제됩니다.

**화상 정령**
- 적중한 몬스터에게 `MonsterBurnEffect` 컴포넌트를 붙여 화상 상태이상을 적용, 몬스터 스프라이트를 화상 색으로 틴트합니다.
- ⚠️ **화상 색이 문서(빨간색)와 다릅니다** — 실제 기본값은 **주황색**(RGB 1, 0.45, 0.1, "타오르는 주황 불꽃색"으로 코드에 주석됨)입니다.
- **2026-08-20 갱신**: `burnDuration`이 0(무한 지속)에서 **10초**로 변경됐습니다. 다만 여전히 문서 확정값(6초)과는 다릅니다.
- **화상↔빙결 상호 배제**: 화상을 걸 때 그 몬스터에게 이미 빙결 효과가 있으면 자동으로 제거합니다 (두 상태이상이 동시에 걸리지 않도록).

**빙결 정령**
- 적중한 몬스터에게 `MonsterFreezeEffect` 컴포넌트를 붙여, `IMonsterMovement` 구현체를 전부 비활성화하고 물리 속도를 0으로 고정 — "이동/공격 정지" 설계와 정확히 일치합니다.
- 지속시간 3초는 문서와 일치합니다.
- ⚠️ **빙결 색이 문서(파란색)와 다소 다릅니다** — 실제 기본값은 **하늘색에 가까운 색**(RGB 0.4, 0.8, 1, "차가운 하늘색"으로 코드에 주석됨)입니다.

> 색상/지속시간/쿨타임 등 수치 불일치는 `스탯_기획서.md` 2.2·4.2·4.3절에도 함께 표시해뒀습니다. 데이터 에셋 값을 문서 확정값으로 채워 넣는 작업이 남아있습니다.

### 3.9 발견된 버그 — 여러 몬스터가 같이 타겟팅됨 (2026-08-20 발견, 수정 예정)

부원이 폭발 정령 구현 중 발견한 버그로, **아직 수정되지 않은 상태**입니다.

- 원인 분석과 수정은 프로그래머가 진행 예정입니다. 자세한 내용은 `QA_테스트_계획서.md` 10장 참고.

## 5. 애니메이션

### 5.1 애니메이션 종류 및 스펙

| 종류 | 설명 | 재생 속도 |
|---|---|---|
| 멈춤 (기본) | 정령이 제자리에 떠 있는 대기 상태 | 기준 속도 (10프레임) |
| 이동 | 정령이 플레이어를 따라 이동하는 상태 | 멈춤의 2배 속도 |

| 상호작용 (변신 효과 적용) | 정령이 상호작용(발판 생성 등)을 실행하는 상태, 변신 효과가 함께 적용됨 | 기준 속도 (10프레임) |

### 7.8 실제 구현 현황 — 정령 여러 마리 동시 운용 마무리 (2026-08-28 추가)

추가 정령이 여러 마리(플랫폼 특화만 최대 3개)일 때의 상호작용이 정리됐습니다.

- **설치 마커 색상이 실제로 출격할 정령의 색을 따라갑니다** — `PlatformClickMarker.cs`가 `FairyManager.GetBestFairyForPlatform()`으로 어떤 정령이 나갈지 미리 확인해서 그 정령의 `SpriteRenderer.color`를 마커에 그대로 입힙니다. 2장에서 정한 "마커 색상은 정령 색을 따라간다"는 규칙이 정령이 여러 마리인 상황까지 포함해 구현 완료됐습니다.
- **다른 마커를 클릭하면 활성화되어 있던 다른 모든 정령의 플랫폼이 한꺼번에 해제됩니다** (`FairyManager.RevertAllActivePlatforms()`) — 정령이 여러 마리라도 플랫폼은 항상 최대 1개만 유지되도록 정리됐습니다.
- **플랫폼 특화 정령 3종이 각자 맞는 플랫폼 프리팹에 정확히 연결됐습니다**: `JumpBoostFairyData→JumpBoostPlatform`, `SpeedBoostFairyData→SpeedBoostPlatform`, `BarrierFairyData→BarrierPlatform`. 지난번까지는 데이터 값이 전부 기본값이라 어떤 정령이 어떤 플랫폼을 만드는지 불확실했는데, 이제 타입별로 정확히 매칭됩니다.
- ⚠️ 다만 `Damage`/`CoolTime` 수치 자체는 여전히 기본값(1/0.5)이라, `스탯_기획서.md`의 정령별 확정 수치는 아직 입력되지 않은 상태입니다.

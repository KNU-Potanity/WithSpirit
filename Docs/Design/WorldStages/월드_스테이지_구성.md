# 월드/스테이지 구성 기획서

## 0. 문서 목적

확장 단계의 테마(월드)별 스테이지 구성, 정령 등장 진행, 스토리 개요, 클리어·게임오버 조건을 정리합니다.

---

## 1. 테마(월드) 구성

| 테마 | 배경 | 스테이지 수 | 정령 등장 |
|---|---|---|---|
| 테마 1 | 마을 또는 도시 | 1 스테이지 (약 5분 분량, 튜토리얼 격) | 기본 정령만 등장 |
| 테마 2 | 변방 | 2 스테이지 | 추가 정령 1~2개 등장 |
| 테마 3 | 숲 | 2 스테이지 | 추가 정령 최대 개수(3개)까지 등장 |

> 기본 테마는 총 3개입니다. 테마 2(변방)는 마을과 숲 사이 경계 지역이라는 컨셉으로, 타일도 마을·숲 타일셋을 함께 사용합니다 (전용 타일셋 없이 의도적으로 혼용).

### 1.1 테마 1 상세 (튜토리얼)

1 스테이지를 두 파트로 구성합니다.

| 파트 | 내용 |
|---|---|
| 앞 파트 | 정령 없이 진행. 조작키(이동·점프) 튜토리얼. 중간에 플레이어 혼자서는 통과할 수 없는 구간이 등장 |
| 전환 | 위 구간에서 정령이 등장해 문제를 해결 → 후반부로 진입 |
| 뒤 파트 | 정령 사용법(마커, 클릭 상호작용) 튜토리얼 |

### 1.5 실제 구현 현황 — 데모 스테이지 1 완성

`Stage1.unity`이 처음부터 끝까지 플레이 가능한 데모 스테이지로 완성됐습니다.

| 그룹 | 배치 내용 |
|---|---|
| Interactables | 정령 플랫폼 설치 장소(`PlatformPlace`) 1개 |
| Hazards | `Thorn` 프리팹 12개 (개별 프리팹 배치 방식) |
| Monsters | 버섯(`Mushroom`) 1마리 |
| Boss | 미배치 (테마 1은 보스 없음) |
| Decoration | 미배치 |

정령 시스템(`Fairy`, `FairyManager`, `MousePointer`)도 함께 배치되어 기본 정령으로 몬스터 공격·플랫폼 설치까지 플레이할 수 있으나, **정령 획득 UI는 아직 Stage1에 배치되지 않았습니다** — 기본 정령 하나로만 플레이하는 데모입니다.

⚠️ 가시 배치 방식이 스테이지마다 다릅니다 — Stage1은 `Thorn.prefab` 낱개 배치, Stage2·3은 `HazardTilemap`(전용 Tilemap) 방식. 통일 여부 결정 필요.

### 1.7 실제 구현 현황 — Stage2 가시 타일 배치

`HazardTilemap`에 가시 타일 17개(`tile_thorn_ceiling` 14개 + `Trap` 3개)가 배치됐습니다.

⚠️ 전부 천장용이거나 `Trap`이고, 바닥용 `tile_thorn.asset`은 쓰이지 않았습니다 — 의도한 배치인지 확인 필요. ⚠️ `Trap.asset`이 `tile_thorn.asset`과 동일한 스프라이트를 쓰는 중복 타일 에셋으로 확인되어(네이밍 규칙 미준수, `Hazards/` 폴더 밖 위치) 정리가 필요합니다.

### 1.8 실제 구현 현황 — Stage2 카메라 끝 거리 조절

`CameraBounds`가 실제 지형 크기(X: -1~77, Y: -3~7)에 맞춰 X: -2~78, Y: -4~8로 확정됐습니다. `Canvas.prefab`의 `CanvasScaler`(1920×1080 기준)와 `HeartContainer` 좌상단 앵커 고정으로, 카메라 이동과 무관하게 HUD가 화면에 고정됩니다.

### 1.9 실제 구현 현황 — Stage3 보스 배치 및 골 지점 조정

밤 나무(`BossEnt`)가 Stage3의 `Boss` 그룹에 배치됐고(`BossEntData` 연결 확인), `GoalPoint`가 실제 지형 끝(X 최대 약 118) 근처인 `(111.9, 35.43)`으로 재배치됐습니다.

### 1.10 실제 구현 현황 — 스테이지 2 완성

| 종류 | 배치 수 |
|---|---|
| 버섯 | 4마리 |
| 스켈레톤 | 3마리 |
| 슬라임 | 2마리 |

Stage1(마을 계열)·Stage3(숲 계열)와 달리 마을 계열(버섯)과 변방 계열(스켈레톤·슬라임)이 섞여 배치되어 1.1절의 "테마 2는 마을·숲 혼용" 컨셉과 일치합니다. 보스는 배치되지 않았습니다 (`몬스터_기획서.md` 3장 "보스는 테마 3에만 등장"과 일치). `GoalPoint`는 `(71.6, 2.6)`입니다.

### 1.11 실제 구현 현황 — 스테이지 3 거의 완성

`HazardTilemap`에 가시 타일 114개(`tile_thorn_ceiling` 68개 + `Trap` 46개)가 채워졌습니다 (Stage2와 마찬가지로 바닥형 `tile_thorn`은 미사용). 몬스터·발판·설치 장소·보스·골 지점은 1.6·1.9절과 동일합니다.

⚠️ 아직 비어있는 부분: `Decoration` 그룹 미배치, 설치 장소 12개 중 7개가 여전히 `PlatformPlace.prefab`에 연결되지 않은 상태.

### 1.12 실제 구현 현황 — 마우스 포인터 프리팹화

커스텀 마우스 포인터(`CustomMousePointer.cs`)가 재사용 프리팹(`Prefabs/UI/MousePointer.prefab`)으로 만들어져 `Stage2`·`Stage3`에 배치됐습니다. ⚠️ Stage1은 아직 이 프리팹을 쓰지 않고 개별(loose) 오브젝트로 남아있어, 이후 이 프리팹으로 교체하는 것이 관리에 유리합니다.

## 3. 스테이지 구성 요소

스테이지는 아래 요소들로 구성됩니다.

- 플랫폼 (일반·이동·무너짐·스탯변화 — `발판_확장_기획서.md`)
- 장애물 (가시, 낙사 등 기존 MVP 요소)
- 뒷배경
- 장식
- 몬스터 (`몬스터_기획서.md`)
- 설치 장소 (정령이 플랫폼을 생성할 수 있는 지점)

### 3.1 맵 배치 순서

스테이지를 실제로 배치할 때는 아래 순서로 쌓습니다: 1. 플랫폼 → 2. 배경 → 3. 상호작용 가능한 타일(설치 장소 등) → 4. 몬스터 → 5. 보스 → 6. 장식

## 5. 게임 클리어 기준

| 단위 | 조건 |
|---|---|
| 스테이지 | 각 스테이지의 도착 지점에 도달하면 클리어 |
| 게임 전체 | 최종 스테이지(테마 3)에서 보스(밤 나무) 처치 |

### 5.1 실제 구현 현황 — 트로피 도달 시 스테이지 전환

`GoalTrigger.cs`가 클리어 로그 출력에서 **실제 다음 씬 로드**로 확장됐습니다.

| 현재 스테이지 | 골 도달 시 이동할 씬 |
|---|---|
| `Stage1` | `Stage2` |
| `Stage2` | `Stage3` |
| `Stage3` | `StartScene` (게임 완료 후 시작 화면으로 복귀) |

`Stage1`/`Stage2`/`Stage3`/`StartScene` 모두 Build Settings에 등록되어 있어 실제 빌드에서도 씬 전환이 정상 동작합니다 (`LoadSceneMode`는 3개 스테이지 모두 Single).

## 6. 리스폰 / 생명

- 리스폰 방식은 MVP와 동일하게 즉시 시작 지점으로 복귀합니다 (체크포인트 없음).
- 플레이어 체력은 하트 아이콘으로 표시되며, 최대 개수는 **4개**입니다.
  - 낙사: 체력이 즉시 0으로 감소 (하트 전부 소진 → 8장 게임 오버 조건 트리거)
  - 낙사를 제외한 데미지(몬스터 접촉, 원거리 공격, 가시 등): 하트 1씩 감소

### 6.1 하트 UI

| 항목 | 내용 |
|---|---|
| 최대 개수 | 4개 |
| 위치 | 화면 좌측 상단 |
| 배치 방식 | 왼쪽부터 오른쪽으로 4개를 가로로 나열, 현재 체력만큼 채워진 하트로 표시 |
| 채워진 하트 | 빨간색 채우기 + 검정색 외곽선 |
| 빈 하트 | 검정색 단색 |

`HeartUI.cs`는 색 틴트가 아니라 **하트 개당 스프라이트를 통째로 교체하는 방식**으로 구현되어 있습니다 (`fullHeartSprite`/`emptyHeartSprite`).

| 스프라이트 필드 | 실제 연결된 에셋 | 비고 |
|---|---|---|
| `fullHeartSprite` | `Assets/_Project/Art/UI/ui_heart_full.png` | Unity 자체 기능으로 만든 임시 플레이스홀더, 정식 아트로 교체 예정 |
| `emptyHeartSprite` | `Assets/_Project/Art/UI/ui_heart_empty.png` | 위와 동일 |

> 검토했던 "2-레이어 색 틴트" 방식과 Flaticon 기반 이미지 방식 모두 채택되지 않았습니다. 참고용으로 남아있는 `Assets/UI/Icons/Heart/heart.png`, `heart_fill.png`(Flaticon 기반)는 현재 어디에도 연결되지 않은 미사용 파일입니다. 정식 아트로 채택되기 전까지는 출처 표기 의무가 없습니다.

|---|---|
| 배경 음악 | 슬라이더, 기본값 80% |
| 효과음 | 슬라이더, 기본값 80% |

### 10.3 설정 — 조작 방법 화면

같은 설정 화면에서 상단 탭을 **조작 방법**으로 전환하면 나옵니다.

| 행동 | 조작키 |
|---|---|
| 왼쪽 이동 | a |

### 10.5 폰트 교체 (NeoDunggeunmo)

한글 텍스트가 네모(□)로 깨져 보이던 문제 해결 과정에서 폰트를 교체했습니다. 출처·라이선스가 불명확했던 `DUNGGEUNMO SDF.asset` 대신, `Assets/_Project/Fonts/neodgm SDF.asset`(NeoDunggeunmo, 원본 파일 `neodgm.ttf`)를 사용 중입니다. 정령 선택 UI·시작 화면·설정 화면의 TMP 텍스트 전부에 적용되어 있습니다.

- 글리프 423개, 아틀라스 2048×2048(Static 빌드 방식)로 실제 게임에 쓰이는 글자만 포함해, 전체 한글을 다 구웠을 때 발생하는 용량·메모리 문제를 피했습니다.
- 출처: https://neodgm.dalgona.dev/ — 상업적 사용이 가능한 오픈소스 폰트로 확인되어 `에셋_출처_라이선스_관리.md` 4장에 기록했습니다.

### 10.6 실제 구현 현황 — 시작 화면 UI 마감

모든 텍스트(21개)가 TMP + NeoDunggeunmo(10.5절) 폰트로 통일되어 있고, `Canvas`에 `CanvasScaler`(Scale With Screen Size, 1920×1080)가 설정되어 해상도가 달라져도 UI 비율이 유지됩니다.

⚠️ `SettingPanel`이 씬 시작 시 기본적으로 켜져 있던 문제를 비활성 상태로 수정했습니다. `SettingsButton` 텍스트 끝에 불필요한 줄바꿈이 하나 있으나 기능엔 영향 없습니다.

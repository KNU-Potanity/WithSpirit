# 2D 플랫포머 게임 기획서 (확장 기능)

## 0. 문서 목적

이 문서는 `플랫포머_게임_기획서.md`에 정의된 **핵심 기능 이후에 추가할 수 있는 확장 기능**을 정리한 문서입니다.

- 핵심 기획서는 장르를 정의하는 최소 기능만 다루고, 이 문서는 **그 외 선택 가능한 기능**을 다룹니다.

---

## 1. 확장 기능 목록

| 분류 | 기능 | 상태 | 비고 |
|---|---|---|---|
| 이동 | 더블 점프, 대시, 벽 점프 | 후보 | 2단 점프는 정령(플랫폼 특화)의 발판 효과로 채택됨 — `정령_시스템_기획서.md` 3.2절 |
| 지형 | 이동 발판, 무너지는 발판 | 채택 | `발판_확장_기획서.md` 참고 |
| 지형 | 스프링 | 후보 | 미정 |
| 적 | 일반 적, 보스 | 채택 | `몬스터_기획서.md` 참고 |
| 수집/보상 | 코인, 젬, 랭크 평가 | 폐기 | 재화 시스템 없음으로 결정 — `월드_스테이지_구성.md` 9장 참고 |
| 생명/체력 | 체력 게이지(하트) | 채택 | `월드_스테이지_구성.md` 6장 참고 |
| 생명/체력 | 체크포인트, 생명 제한 | 후보 | 현재는 즉시 리스폰 유지 |
| 파워업 | 크기 변화, 무적, 속도 강화 | 정령으로 대체 | 정령 시스템이 파워업 역할을 겸함 — `정령_시스템_기획서.md` 참고 |
| UI | HUD(수집물 표시) | 채택 (범위 변경) | 하트·정령 선택 UI로 필요 — 상세는 추후 UI 설계에서 확정 |
| UI | 일시정지 메뉴 | 후보 | 미정 |
| 카메라 | 화면 흔들림, 줌, 컷씬 연출, 자동 스크롤 | 보류 | 확장 단계에서도 카메라 로직은 수정하지 않기로 결정 — `월드_스테이지_구성.md` 4장 참고 |
| 사운드 | 효과음, BGM | 후보 | 사운드 모듈로 추후 추가 (필요 항목은 `사운드_큐_리스트.md` 참고) |
| 기타 | 스토리 | 채택 | 방향성만 확정, 구체 내용은 미작성 — `월드_스테이지_구성.md` 2장 참고 |
| 기타 | 멀티플레이, 레벨 에디터 | 후보 | 장기 로드맵 항목 |

> 상태 값 정의 — 채택: 설계 확정 및 상세 문서 존재 / 후보: 아직 채택 여부 미정 / 보류: 검토했으나 당장 하지 않기로 결정 / 폐기: 하지 않기로 확정.

> 이 목록에서 후보/보류로 남은 기능은 당장 안 만든다는 의미일 뿐, 핵심 기능 설계 시 이 기능들이 들어올 자리를 막지 않도록 구조를 짜는 것이 중요합니다.

## 2. 확장을 고려한 설계 원칙

핵심 기능을 구현하는 단계에서도 아래 원칙을 지켜서, 나중에 이 확장 기능들을 붙이기 쉽게 만듭니다.

1. **이동 로직과 충돌 로직을 분리한다.**
 - 캐릭터의 이동 계산과 지형 충돌 처리를 독립된 모듈로 나눠서, 추후 새로운 이동 기술(대시 등)을 추가해도 충돌 로직을 건드릴 필요가 없도록 합니다.

2. **지형 오브젝트는 '타입'으로 구분한다.**
 - 지금은 일반 발판과 즉사 장애물 2종류만 있지만, 이동 발판·무너지는 발판·스탯 변화 발판 등 새로운 타입을 추가할 때 타입만 추가하면 되도록 설계합니다 (`발판_확장_기획서.md` 참고).

3. **리스폰 로직은 별도의 시스템으로 둔다.**
 - 지금은 단순히 시작 지점으로 돌아가지만, 확장 단계에서 하트(체력) 시스템이 추가된 것처럼 리스폰 지점/조건을 결정하는 로직을 분리해 둡니다.

4. **레벨 데이터는 코드와 분리한다.**
 - 스테이지 구조(발판 위치, 장애물 위치 등)는 별도의 데이터 형태로 관리해서, 몬스터나 설치 장소가 추가되어도 레벨 데이터 형식만 확장하면 되도록 합니다.

5. **UI/사운드는 처음부터 만들지 않되, 이벤트 단위로 동작을 구분해 둔다.**
 - 예: 점프했다, 장애물에 닿았다, 도착 지점에 도달했다, 하트가 감소했다 같은 이벤트는 명확히 구분해 두고, 사운드나 UI가 나중에 이 이벤트에 반응하도록 붙이기 쉽게 합니다.

6. **카메라는 모드 전환이 가능한 구조로 둔다.**
 - 기본은 플레이어 추적형이며, 확장 단계에서도 당장은 수정하지 않기로 했지만 추후 필요해질 경우를 대비해 카메라 동작은 별도 모듈로 분리된 상태를 유지합니다.

## 3. 참고용 우선순위 가이드 (선택)

확장 기능을 추가하고 싶은 부원이 있다면, 아래 순서를 참고하면 도움이 될 수 있습니다. 다만 이는 강제 사항이 아니며, 관심 있는 기능을 자유롭게 먼저 선택해도 무방합니다.

1. **정령 시스템** — 채택된 확장의 핵심 축, 스탯·기본 정령·몬스터·발판·추가 정령 순으로 설계 진행 중
2. **몬스터 시스템** — 플랫포머 경험에 가장 큰 영향을 주는 요소
3. **UI** — 하트·정령 선택 등 플레이 피드백 강화
4. **사운드** — 새로 추가되는 이벤트(공격, 하트 감소 등)에 맞춰 확장
5. **카메라 확장, 기타** — 게임의 톤과 방향성이 더 정해진 후 적용

> 부원이 아무도 손대지 않는 항목이 있어도 괜찮습니다. 이 문서의 후보/보류 항목은 할 수 있으면 좋은 것이며 반드시 해야 하는 것이 아닙니다.

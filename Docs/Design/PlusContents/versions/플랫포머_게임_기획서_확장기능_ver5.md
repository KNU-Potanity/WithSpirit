# 2D 플랫포머 게임 기획서 (확장 기능)

## 0. 문서 목적

이 문서는 `플랫포머_게임_기획서.md`에 정의된 **핵심 기능 이후에 추가할 수 있는 확장 기능**을 정리한 문서입니다.

- 핵심 기획서는 "장르를 정의하는 최소 기능"만 다루고, 이 문서는 **그 외 선택 가능한 기능**을 다룹니다.
- 아래 항목들은 **반드시 구현해야 하는 것이 아니라, 동아리 부원들이 자율적으로 선택해서 추가할 수 있는 후보 목록**입니다. 일부만 골라서 구현하거나, 전혀 추가하지 않아도 무방합니다.
- 누군가 새로운 기능을 추가하고 싶을 때, 핵심 기획서의 구조를 깨지 않고 끼워 넣을 수 있도록 가이드 역할을 하는 문서입니다.

---

## 1. 확장 기능 목록

| 분류 | 기능 | 비고 |
|---|---|---|
| 이동 | 더블 점프, 대시, 벽 점프 | 이동 모듈에 옵션으로 추가 예정 |
| 지형 | 이동 발판, 무너지는 발판, 스프링 | 지형 모듈에 타입 추가로 확장 |
| 적 | 일반 적, 보스 | 별도의 적 시스템 문서로 추후 작성 |
| 수집/보상 | 코인, 젬, 랭크 평가 | 별도의 보상 시스템으로 추후 추가 |
| 생명/체력 | 체크포인트, 생명 제한, 체력 게이지 | 리스폰 모듈 확장으로 추가 |
| 파워업 | 크기 변화, 무적, 속도 강화 | 별도의 파워업 시스템으로 추후 추가 |
| UI | HUD(수집물 표시), 일시정지 메뉴 | 화면 표시 모듈로 추후 추가 |
| 카메라 | 화면 흔들림, 줌, 컷씬 연출, 자동 스크롤 | 기본 추적 카메라에 옵션/모드 추가로 확장 |
| 사운드 | 효과음, BGM | 사운드 모듈로 추후 추가 (필요 항목은 `사운드_큐_리스트.md` 참고) |
| 기타 | 스토리, 멀티플레이, 레벨 에디터 | 장기 로드맵 항목 |

> 이 목록은 "당장 안 만든다"는 의미일 뿐, 핵심 기능 설계 시 이 기능들이 들어올 자리를 막지 않도록 구조를 짜는 것이 중요합니다. (예: 적 시스템이 없어도, 충돌 처리 구조는 적이 추가될 걸 가정하고 분리)

## 2. 확장을 고려한 설계 원칙

핵심 기능을 구현하는 단계에서도 아래 원칙을 지켜서, 나중에 이 확장 기능들을 붙이기 쉽게 만듭니다.

1. **이동 로직과 충돌 로직을 분리한다.**
   - 캐릭터의 이동 계산과 지형 충돌 처리를 독립된 모듈로 나눠서, 추후 새로운 이동 기술(대시 등)을 추가해도 충돌 로직을 건드릴 필요가 없도록 합니다.

2. **지형 오브젝트는 '타입'으로 구분한다.**
   - 지금은 '일반 발판'과 '즉사 장애물' 2종류만 있지만, 나중에 '이동 발판', '스프링' 등을 추가할 때 새로운 타입만 추가하면 되도록 설계합니다.

3. **리스폰 로직은 별도의 시스템으로 둔다.**
   - 지금은 단순히 시작 지점으로 돌아가지만, 추후 체크포인트나 생명 시스템이 추가될 걸 가정해 "리스폰 지점을 결정하는 로직"을 분리해 둡니다.

4. **레벨 데이터는 코드와 분리한다.**
   - 스테이지 구조(발판 위치, 장애물 위치 등)는 별도의 데이터 형태로 관리해서, 나중에 적이나 수집 아이템이 추가되어도 레벨 데이터 형식만 확장하면 되도록 합니다.

5. **UI/사운드는 처음부터 만들지 않되, 이벤트 단위로 동작을 구분해 둔다.**
   - 예: "점프했다", "장애물에 닿았다", "도착 지점에 도달했다" 같은 이벤트는 명확히 구분해 두고, 사운드나 UI가 나중에 이 이벤트에 반응하도록 붙이기 쉽게 합니다.

6. **카메라는 모드 전환이 가능한 구조로 둔다.**
   - 기본은 플레이어 추적형이지만, 추후 자동 스크롤이나 카메라 줌 같은 모드를 추가할 때 기존 추적 로직을 갈아엎지 않도록 카메라 동작을 별도 모듈로 분리합니다.

## 3. 참고용 우선순위 가이드 (선택)

확장 기능을 추가하고 싶은 부원이 있다면, 아래 순서를 참고하면 도움이 될 수 있습니다. 다만 이는 강제 사항이 아니며, 관심 있는 기능을 자유롭게 먼저 선택해도 무방합니다.

1. **적 시스템** — 플랫포머 경험에 가장 큰 영향을 주는 요소
2. **수집/보상** — 코인 등 간단한 보상 요소로 탐험 동기 부여
3. **UI/사운드** — 플레이 피드백 강화
4. **파워업** — 게임플레이 변주 추가
5. **생명/체력 확장, 카메라 확장, 기타** — 게임의 톤과 방향성이 정해진 후 적용하면 좋은 항목

> 부원이 아무도 손대지 않는 항목이 있어도 괜찮습니다. 이 문서의 모든 항목은 "할 수 있으면 좋은 것"이며 "반드시 해야 하는 것"이 아닙니다.

# 발판 확장 기획서

## 0. 문서 목적

MVP 단계의 발판(일반 발판, 즉사 장애물)에 이어, 확장 단계에서 추가되는 발판 종류를 정리합니다. 기존 발판 정의는 `플랫포머_게임_기획서.md` 2.2절을 참고하세요.

---

## 1. 신규 발판 종류

| 종류 | 동작 방식 | 비고 |
|---|---|---|
| 이동 발판 | 전방향(좌우·상하 등)으로 움직이는 발판 | 미착수 |
| 무너지는 발판 | 밟은 지 1초 후 아래로 낙하, 다른 바닥에 부딪히면 소멸(없으면 낙사 판정까지 계속 낙하) | 구현 완료 (5.1절) |
| 스탯 변화 발판 | 밟으면 플레이어 스탯이 변화 — 아래 3종으로 확정 | 구현 완료 (5.2~5.4절) |

### 1.1 스탯 변화 발판 — 3종 확정

| 종류 | 효과 |
|---|---|
| 이속 증가 발판 | 밟고 3초 동안 이동 속도 1.5배 |
| 점프력 증가 발판 | 원래 점프 높이의 1.5배만큼 더 높이 점프 |
| 데미지 무효화 발판 | 데미지 1회를 막아주는 장막 부여 (1회 소모되면 사라짐) |

> 실제 구현 상세와 설계 대비 차이는 5장 참고.

## 2. 정령이 생성하는 플랫폼과의 관계

- 위 1장 표는 스테이지에 미리 배치된 발판입니다.
- 정령(플랫폼 특화 3종)이 생성하는 발판은 `정령_시스템_기획서.md` 3.2절에 정의되어 있으며, **1.1절의 스탯 변화 발판 3종과 동일한 효과**를 냅니다. **설치 장소**라는 전용 지점에서만 생성됩니다 (`월드_스테이지_구성.md` 3장 참고).

## 3. 게임 오버 요소와의 구분

발판이 아닌 스테이지의 위험 요소는 별도로 관리합니다.

- 가시, 낙사 (기존 MVP)
- 원거리 공격, 접촉 데미지, 디버프 (몬스터 관련 — `몬스터_기획서.md` 참고)

## 5. 실제 구현 현황 — 플랫폼 4종

공통 구조: `PlacedPlatform.prefab`을 베이스로, 루트(Grid + 전용 스크립트) → 자식 `Platform`(Tilemap+Collider+Rigidbody2D). 스테이지에 미리 배치하는 용도로, 정령이 만드는 플랫폼(2장)과는 별개의 프리팹 세트입니다.

### 5.1 무너지는 발판 (`CrumblingPlatform.cs`)

- `fallDelay`(1초)는 설계와 일치.
- ⚠️ 경고 연출이 "금 간 이미지 교체"가 아니라 **좌우 흔들림(Shake, 진폭이 점점 커짐)** 방식입니다.
- 낙하 시 Rigidbody2D를 Kinematic→Dynamic 전환, 다른 콜라이더에 부딪히거나 `destroyBelowY`(-20) 밑으로 가면 삭제 — 설계와 일치.

### 5.2 이속 증가 발판 (`SpeedBoostPlatform.cs`)

`speedMultiplier`(1.5)·`buffDuration`(3초) 모두 설계와 일치. 재탑승 시 지속시간이 갱신되며, 버프 중 플레이어 색이 노란색으로 바뀝니다.

### 5.3 점프력 증가 발판 (`JumpBoostPlatform.cs`)

`jumpMultiplier`(1.5)는 설계와 일치하나, ⚠️ **시간제한이 아니라 "발판 위에 있는 동안만" 적용**되는 방식입니다 (이속 증가 발판과 다름). 버프 중 플레이어 색이 초록색으로 바뀝니다.

- ⚠️ 색상 충돌: `정령_시스템_기획서.md`의 정령 색상(점프력강화=노랑, 이속증가=하늘색)과 실제 플레이어 틴트 색(점프=초록, 이속=노랑)이 서로 다릅니다 — 통일 여부 결정 필요.

### 5.4 데미지 무효화 발판 (`BarrierPlatform.cs` + `BarrierWall.cs`)

- 몬스터는 장막의 존재를 모르고 평소와 똑같이 공격하며, 데미지를 실제로 입히는 순간(`PlayerHealth.TakeDamage()`)에 근처 활성 `BarrierWall`이 있으면 그 호출이 무효화되고 장막이 소멸합니다 — 공격 애니메이션 자체는 항상 정상 재생됩니다.
- 물리적으로 부딪혀오는 몬스터·투사체는 장막의 Collider에 막혀 소멸합니다.
- ⚠️ `PlayerBarrier.cs`라는 별도 컴포넌트가 있으나 `PlayerHealth.TakeDamage()`에서 호출되지 않는 미사용 코드입니다. 실제 장막 판정은 `BarrierWall` 기준으로만 동작합니다.
